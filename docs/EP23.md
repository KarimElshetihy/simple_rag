In this video, the creator sets up an automated deployment pipeline (CI/CD) for a private *GitHub* repository using *GitHub Actions* and an *Ubuntu* VPS. Below are the step-by-step actions performed:

### 1. Initial Setup and User Management

*   **Organization & Repo:** Created a *GitHub* organization (06:41) and a private repository (07:13).
*   **VPS User:** Created a dedicated `github_user` on the server and added them to the `sudo` group (14:15).
*   **SSH Keys:** Generated an SSH key for the `github_user` to access the server (16:30) and used a separate **Deploy Key** to allow the server to securely clone the private repository from *GitHub* (26:40).

### 2. Environment Configuration

*   **Docker & Compose:** Installed *Docker* (35:05) and configured *Docker Compose* to run the project services (37:15).
*   **Port Forwarding:** Used SSH port forwarding (`ssh -L`) to securely access services like *Grafana* locally without exposing ports on the server firewall (59:40 - 1:01:14).

### 3. Automating Service Management

*   **Systemd Service:** Created a custom service file in `/etc/systemd/system/mini-rag.service` (1:09:28) to ensure the *Docker* containers restart automatically after reboots (1:04:05).
*   **Sudo Permissions:** Configured `visudo` to allow `github_user` to run the `systemctl restart mini-rag` command without needing a password (1:15:48).

### 4. GitHub Actions Pipeline

*   **Secrets:** Added the server's IP address and the SSH private key as *GitHub Repository Secrets* for the *Actions* workflow (1:17:18).
*   **Workflow:** Created a `.github/workflows/main.yml` file (1:19:20). The workflow triggers on every `push` to the `main` branch (1:20:40). It uses `appleboy/ssh-action` to connect to the VPS, pull the latest code, and restart the service (1:23:17).

### 5. Troubleshooting

*   **Static IP:** The creator discovered that the VPS IP changed after a reboot. To fix this, he assigned a **Static IP** (Elastic IP) in the cloud provider's networking settings and updated the *GitHub* secret (143:40 - 144:40).

### Key Commands Used

*   **SSH Key Gen:** `ssh-keygen -t rsa -b 4096 -C "comment"` (16:30)
*   **Systemd Reload:** `sudo systemctl daemon-reload` (1:10:17)
*   **Service Status:** `journalctl -u mini-rag -f` (1:11:10)
*   **Port Forwarding:** `ssh -L 4000:localhost:3000 user@server_ip` (1:00:35)
