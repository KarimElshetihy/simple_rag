This course provides a comprehensive guide to building reliable, durable workflows using **Temporal**. Below is the step-by-step breakdown of the processes covered in the video:

## 1. Environment Setup & Temporal Basics (0:00 - 42:00)

*   **Conceptual Overview:** The instructor introduces **Temporal** as a "Durable Execution Platform" designed to handle stateful workflows that can survive failures and retries.
*   **Infrastructure:**
    *   Prepared a server environment for hosting.
    *   Used **Docker Compose** with **PostgreSQL** to perform a self-hosted installation of the Temporal server.
*   **Temporal Web UI:** Explored the interface to inspect workflow history and task states (42:00).

## 2. Building a Plain Python Pipeline (52:48 - 1:22:50)

*   **Initial Design:** Created a synchronous PDF processing script that:
    1.  Downloads a PDF from **AWS S3** using `boto3`.
    2.  Extracts text to **Markdown** using `pymupdf4llm`.
    3.  Uploads the processed Markdown back to S3.
*   **Helpers:** Created helper functions (e.g., `get_s3_client`, `parse_path`) to manage connectivity and file paths.

## 3. Refactoring to Temporal (1:22:50 - 2:46:03)

*   **Project Structure:**
    *   Separated code into `activities.py` (individual units of work), `workflows.py` (business logic orchestration), and `workers.py`.
*   **Integration:**
    *   Implemented `RetryPolicies` and timeouts for fault-tolerant execution.
    *   Converted standard functions into **Temporal Activities** using the `@activity.defn` decorator (1:33:18).
    *   Wrapped activity calls in `workflow.execute_activity` (1:45:44).
*   **Worker:** Set up a worker process to listen to a specific **Task Queue** (`pdf-pipeline-queue`) and run as a `systemd` service.
*   **FastAPI Client:** Built a REST API wrapper using `FastAPI` to trigger workflows synchronously or asynchronously by communicating with the Temporal server (2:14:10).

## 4. AI Contract Review Agent (2:49:00 - 4:47:00)

*   **AI Integration:** Integrated `OpenRouter` to call LLMs for summarizing content and risk assessment.
*   **Advanced Patterns:**
    *   **Activity Heartbeats:** Implemented heartbeats within long-running activities to report progress percentage and status back to the workflow (3:10:40).
    *   **Child Workflows:** Used a parent-child workflow fan-out pattern to process multiple documents in parallel using `asyncio.gather` (3:18:10).
    *   **Human-in-the-Loop:** Designed a review cycle where the workflow pauses and waits for external input using **Temporal Signals** and **Updates** (4:07:00).
    *   **Queries:** Implemented custom queries to inspect the workflow state while it is running (4:25:00).
